# Noctua Fan Control — Тестирование (pytest)
## Назначение
Каталог `tests/` содержит автоматические тесты системы управления вентилятором 
__Noctua NF-A4x20 5V PWM__ для Raspberry Pi 5.

Тесты проверяют корректность алгоритмов, обработку ошибок, работу конфигурации, 
калибровку RPM и взаимодействие компонентов проекта.

> Все тесты выполняются __без доступа__ к физическим `GPIO`, 
> не управляют реальным вентилятором и не требуют `sudo`.

## 2. Установка зависимостей
Для тестирования требуется `Python` и `pytest`.

> Рекомендуется использовать виртуальное окружение `.venv`.

Установка pytest:
```bash
python -m pip install pytest
```

Проверка установленной версии:
```bash
python -m pytest --version
```

> Тестам не требуется установленный `lgpio`

---

## 3. Запуск всех тестов
Все команды выполняются из корня `noctua-fan-control/`.

Запуск:
```bash
python -m pytest
```

Краткий вывод:
```bash
python -m pytest -q
```

Подробный вывод:
```bash
python -m pytest -v
```

## 4. Маркеры pytest
Маркеры позволяют запускать определённые категории тестов независимо друг от друга.

### config — Конфигурация
```bash
python -m pytest -m config -v
```
Проверяет:
1. Валидацию кривых CPU/NVMe и защиту от NaN.
2. Запрет сохранения некорректного LEVEL.
3. AUTO/MANUAL, резервную копию и атомарную запись.
4. Блокировку конкурентных изменений конфигурации.
5. Запрет запуска второго daemon.
6. Безопасное поведение при ошибке hot-reload.


### policy — Управление вентилятором
```bash
python -m pytest -m policy -v
```
Проверяет:
1. Интерполяцию PWM и приоритет CPU/NVMe.
2. Гистерезис 3°C и выдержку 15 секунд. 
3. Усреднение NVMe и потерю температурного датчика. 
4. Режим MANUAL и приоритет аварийного охлаждения. 
5. Расчёт TACH/RPM и аварийную реакцию. 
6. Start-boost при переходе из PWM=0. 
7. Сравнение RPM с baseline и предупреждение об обслуживании.


### calibration — Калибровка RPM
```bash
python -m pytest -m calibration -v
```
Проверяет:
1. Запрет калибровки без работающего daemon. 
2. Отмену калибровки при несовпадении PWM. 
3. Сохранение baseline при отсутствии RPM. 
4. Успешную калибровку и восстановление AUTO.


### runtime — Мониторинг и daemon
```bash
python -m pytest -m runtime -v
```
Проверяет:
1. Определение устаревшего `status.json`.
2. Работу CLI и read-only мониторинга CPU/HAT.
3. Три цикла управления с подменённым GPIO.

## 5. Комбинирование маркеров
Запуск нескольких категорий:
```bash
python -m pytest -m "config or policy" -v
```

Запуск всех тестов, кроме калибровки:
```bash
python -m pytest -m "not calibration" -v
```

Просмотр зарегистрированных маркеров:
```bash
python -m pytest --markers
```

Просмотр всех обнаруженных тестов (без выполнения):
```bash
python -m pytest --collect-only -q
```

## 6. Изоляция GPIO
Тесты предназначены для безопасного запуска на обычном компьютере и Raspberry Pi.

В `conftest.py` используются:
- `FakePWM` — имитация PWM-выхода.
- `FakeTACH` — имитация тахометрического входа.
- `FakeFactory` — имитация GPIO-фабрики.
- `project` — фикстура с временной конфигурацией.

Аппаратные модули должны подменяться __до импорта `noctua_daemon.py`__.

Тесты не должны:
- открывать физические GPIO;
- изменять PWM работающего вентилятора;
- записывать данные в рабочий `config.json`;
- запускать системный сервис управления Noctua;
- требовать `sudo`.

Для операций записи используются временные каталоги, предоставляемые `tmp_path`.
